# Refacton 記録と条件確認デモ

**ローカルシミュレーター上で実行中（Preprod未配備）**

生成済み`compiled/contract/index.js`の`Contract`と`ledger()`を、`@midnight-ntwrk/compact-runtime` 0.16.0で実行します。登録・応答・拒否は元のCompact回路の実行結果です。Preprod配備は保留です。このデモにBlockfrostやそのtokenは必要ありません。

## 起動（リポジトリのルートで2コマンド）

Node.js 22以上、npmを使用します。生成物は同梱されているため、画面を開くだけならコンパイラの導入は不要です。

```bash
npm install
npm run demo
```

`http://127.0.0.1:3000`を開きます。初期値はローカルホストのみ待ち受けます。Manusのプレビュー等で必要な場合だけ`HOST=0.0.0.0 npm run demo`を使ってください。この場合、プレビューに接続できる人は独自のダミーセッションを作れます。実ユーザーの秘密を入れないでください。`PORT`で待受ポートを変えられます。

## 記録・条件提示・応答

「01 記録を登録」で`recordQuest`を呼び、台帳の記録の指紋（commitment）・二重登録の防止印（nullifier）・件数を更新します。「02 条件を出す」でquestIdと問いの値（challenge）を確定します。これは画面上の入力準備で、まだ回路は呼びません。「03 売り手が応答」でその2値を引数に`checkAttestation`を実行し、正常終了時だけ「条件に合う」と表示します。

challengeを変えるときは「新しいchallengeを用意」から「条件を出す」で確定してください。入力を変更したままでは応答ボタンを止め、確定済み条件との取り違えを防いでいます。

ここでの「条件」はquestIdと問いの値だけです。業務領域・予算・納期の照合や、項目ごとの見せる／見せないはコントラクトにありません。「60秒の紹介動画を完成」はモックの説明用ラベルです。動画ファイル、内容、実際の完了の事実、発行者の裏付けは扱いません。

「間違った秘密で応答」は、元のuserSecretとは違う一時値をwitnessへ渡します。元回路が`Attestation not found`で止まったことを受けて「合わない」と表示します。「同じ記録を再登録」は同じquestIdとlocalSecretKeyから同じnullifierを作り、元回路の`Quest already recorded by this user`で拒否されます。どちらも台帳の件数とSetsは変わりません。

**`Attestation not found`で停止した確認は有効な取引として送信されず、実際のネットワークでは台帳に何も残りません。デモサーバーの記録は別です。**

## 手元の非公開値と、確認時の公開入力

このデモの手元はローカルNodeプロセスのメモリです。Manusプレビューでは閲覧者の端末ではなくSandboxで動きます。売り手のuserSecret・salt・localSecretKeyの実値をブラウザへ返さず、HTTP・画面・ログにも出しません。秘密入力欄や、外部AI・外部APIへの秘密送信はありません。

questIdは記録時は非公開witnessなので、左に「記録時のみ非公開」と表示します。確認時のquestIdは依頼者が知っている公開入力で、問いの値と一緒に渡します。売り手の秘密・乱数・鍵とは区別しています。

右の上段「台帳の中身」は、生成`ledger()`から読み取るcommitments、nullifiers、counterの実値だけです。下段「デモの記録」はサーバーが記録する回路名・時刻と実行結果で、台帳フィールドではありません。失敗した呼出しもサーバーの記録には残りますが、ネットワーク取引の記録ではありません。

正常終了した確認では「この確認で開示された指紋」に、登録時に生成ledgerから読み取り、その確認の成功ログが参照しているcommitment全文を表示します。「記録の指紋」と同じ値が見えます。これは確認時の公開参照を説明する表示であり、新しい台帳フィールドや登録ではありません。失敗した確認や新しい条件を確定した後には、過去の成功値をその確認の開示値として表示しません。応答バイトとprivate transcriptはHTTPへ返しません。

**同じ記録への確認どうしは結び付く（この実装の限界、Wave 3で対応）**

challengeが変わり応答が変わっても、同じ公開commitmentの参照が残ります。発行者・失効・本人性の仕組みも未実装です。

セッションごとに状態を分け、秘密も台帳もディスクへ保存しません。「最初から」またはサーバ再起動で消え、操作のないセッションは1時間で期限切れになります。ウォレット鍵・シード・APIキーは扱いません。

## 回路の呼び方と実行チェック

呼出しは`test/quest-attestation.test.js`に従っています。旧READMEやTOOLCHAIN.mdの使い方例は使用しません。秘密は`Contract`に登録したwitness関数から供給し、公開引数だけを回路へ渡します。

```javascript
const result = contract.circuits[name](context, ...args);
context = result.context;
const publicState = ledger(context.currentQueryContext.state);
```

`recordQuest`には公開引数を追加せず、`checkAttestation`は`challenge, questId`の順に渡します。既存デモのサーバー・シミュレーターの呼出し自体は変更していません。

```bash
npm test
npm run demo:check
```

元Jestの16件と、`demo/`内の追加7件を実行します。コントラクト、生成物、元`test/`の処理・期待値、既存コメントは変更していません。コンパイルには公式Compact 0.31.1ツールが必要です。

## 撮影用の約45秒台本

| 時間 | 操作と説明 |
| --- | --- |
| 0–10秒 | ローカル実行表示と、左のquestId「記録時のみ非公開」を見せる |
| 10–20秒 | 記録を登録し、右上の記録の指紋・二重登録の防止印・件数1を見る |
| 20–32秒 | questIdと問いの値を出して応答。「条件に合う」と開示指紋が登録指紋と同じ全文になることを見る |
| 32–40秒 | 間違った秘密で「合わない」。同じ記録の再登録が拒否され、件数1のままを見る |
| 40–45秒 | 「台帳の中身は記録の指紋、二重登録の防止印、件数だけ」 |

依頼者の業務条件を伏せたまま照合する設計と、依頼者が応答を自分で確かめる処理がまだない点は、`docs/wave3-notes.md`の設計項目に記すだけで、今回は実装しません。
