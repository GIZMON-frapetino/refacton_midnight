# Refacton 記録と条件確認デモ

**ローカルシミュレーター上で実行中（Preprod未配備）**

生成済み`compiled/contract/index.js`の`Contract`と`ledger()`を、`@midnight-ntwrk/compact-runtime` 0.16.0で実行します。登録・応答・拒否は見た目だけのモックではなく、元のCompact回路の実行結果です。ネットワーク取引、ウォレット接続、実ユーザーの作業完了の事実認定、発行者の裏付けは行いません。

## 起動（リポジトリのルートで2コマンド）

Node.js 22以上、npmを使用します。生成物はリポジトリ内にあるため、画面を開くだけならコンパイラの再導入は不要です。

```bash
npm install
npm run demo
```

`http://127.0.0.1:3000`を開きます。初期値はローカルホストのみ待ち受けます。Manusのプレビュー等で必要な場合だけ`HOST=0.0.0.0 npm run demo`を使ってください。この場合、プレビューに接続できる人は独自のダミーセッションを作れます。実ユーザーの秘密を入れないでください。`PORT`で待受ポートを変えられます。

## 画面の流れ

challengeを新しくする場合は「新しいchallengeを用意」を押してから「条件を出す」で確定してください。questIdやchallengeを変更したまま応答する操作は止め、確定済み条件との取り違えを防いでいます。

「01 記録を登録」で`recordQuest`を呼び、右側の生成ledgerから読み取ったcommitment・nullifier・件数を表示します。「02 条件を出す」でquestIdの選択と64桁のchallengeを確定します。この操作は画面の入力準備であり、まだ回路は呼びません。「03 売り手が応答」でその条件を引数に`checkAttestation`を実行します。回路が正常に終了したときだけ依頼者の結果欄に「条件に合う」と出します。

「間違った秘密で応答」は、元のuserSecretとは違う一時値をwitnessへ渡します。元回路の`Attestation not found`による拒否を「合わない」と表示します。「同じ記録を再登録」は、元のquestIdとlocalSecretKeyから同じnullifierを作る回路が`Quest already recorded by this user`で拒否します。拒否後も件数とSetsは変わりません。

## 手元・公開状態・デモログの境界

このデモの手元はローカルNodeプロセスのメモリです。questId、version、userSecret、localSecretKey、saltは暗号用乱数等から生成した撮影用のダミー入力です。秘密値はブラウザへ返さず、伏せ字だけを表示します。Manusプレビューでは、手元の処理は閲覧者の端末ではなくSandboxで動きます。秘密入力欄、外部AI、外部APIへの秘密送信はありません。画面の「60秒の紹介動画を完成」は説明用ラベルで、動画ファイルや完了の事実をこのコントラクトが扱うわけではありません。

台帳フィールドはcommitments、nullifiers、counterの3つです。登録時のquestIdはwitnessですが、**checkAttestationではquestIdとchallengeが公開入力です**。確認のcommitment参照と32バイトの応答も公開側の処理になります。画面の依頼者結果欄は「条件に合う／合わない」だけに絞っていますが、公開回路のすべての値が秘密になるという意味ではありません。応答バイトとprivate transcriptはHTTPへ返しません。

回路名・時刻・成否はローカルのデモ実行ログです。これらを台帳フィールドと混同しないよう画面でも別枠にしています。失敗した回路呼出しもデモログに残りますが、チェーン上の取引記録ではありません。確認ログのcommitmentは、登録時に生成ledgerから読んだ既存値を参照表示しています。新たな公開値が台帳Setへ増えるわけではありません。

**既知の限界：確認時に同じcommitmentを公開参照するため、同じ記録の確認同士は結び付き得ます。** これは現行実装の公開値再利用による限界です。challengeが変わって応答が変わることは、この相関をなくすことではありません。発行者・失効・本人性の仕組みも未実装です。

セッションごとに状態を分け、秘密も台帳もディスクへ保存しません。「最初から」またはサーバ再起動で状態が消えます。操作のないセッションは1時間で期限切れになります。ウォレット鍵・シード・APIキーは扱いません。

## 実行チェック

```bash
npm test
npm run demo:check
```

`npm test`は元のJest 16件をそのまま実行します。追加の`demo:check`はNode標準のテストランナーで、実台帳更新、二重登録拒否、間違った秘密、違うquestId、2回の確認、入力エラー、HTTPとセッション分離を7件で確認します。元の`test/`や期待値は変更していません。

`npm run compile`には`TOOLCHAIN.md`の公式Compact 0.31.1ツールが必要です。今回のデモ用コミットは既存コントラクト・生成物を変更しません。依存の初回インストール以外はローカルで動きます。

## 撮影用の約45秒台本

| 時間 | 操作と説明 |
| --- | --- |
| 0–10秒 | 上部のローカル実行表示を見せる。左は伏せ字のwitness、右はシミュレーター台帳 |
| 10–20秒 | 記録を登録。右のcommitment・nullifier・件数1を見せる |
| 20–32秒 | 条件を出して売り手が応答。「条件に合う」を見せる |
| 32–40秒 | 間違った秘密で「合わない」。同じ記録の再登録が拒否され、件数1のまま |
| 40–45秒 | 「台帳には指紋、nullifier、件数が残ります。回路名と時刻はデモログです。確認同士の結び付きはWave 3で対応を予定しています」 |

元の台本の「指紋と回路名と時刻だけ」という締めは、実際の台帳フィールドに合わせて上記へ言い換えています。
